# Первая сборка MVP: состав и маршрут развития

После [[mvp-product-analogues|углублённого обзора аналогов]] и [[mvp-oss-components|повторного чтения OSS]] выбран первый формат: **локальное расширение Chrome/Edge с боковой панелью и отдельной рабочей областью**. Оно помогает разбирать сохранённые объявления. Первая реализация находится в [каталоге mvp](https://github.com/cj-isus/avitolog/tree/main/mvp); [веб-прототип](https://cj-isus.github.io/avitolog/prototype/) демонстрирует общую рабочую область без установки расширения.

Это первая инженерная сборка с ограниченным сценарием. Она не доказывает оплаченный спрос, точность оценки рынка, работу на текущей авторизованной странице Avito или готовность коммерческого продукта. Исследовательские основания и эти проверки разделены в [[mvp-architecture|архитектуре]].

## Что действительно собрано

| Часть | Готовый компонент | Наша часть и текущая граница |
|---|---|---|
| Расширение, manifest, side panel, workspace | WXT + Vite | Узкий вход по действию пользователя; без постоянного доступа ко всем сайтам |
| Состояния и интерфейс | React + TypeScript | Пять представлений: радар, сравнение, ориентиры, черновик, требования |
| Диалоги | Radix Dialog | Ручное добавление/импорт и досье; управление фокусом, Escape |
| Локальное хранение | Dexie + dexie-react-hooks | Карточки и условия; общий транзакционный upsert, экспорт/импорт |
| Контракт входных данных | Zod | Версионированный JSON, допустимые URL и лимиты; это проверка структуры, не правдивости |
| Ценовая визуализация | Recharts | Цены выбранных предложений; диапазон и медиана без заявления цены сделки |
| Иконки | Lucide | Единый язык управляющих элементов; сохранены уведомления ISC/MIT |
| Предметный отбор | Собственная небольшая логика | Колёса, заявленный диапазон роста, бюджет с резервом; три исхода вместо ложного PASS |

Пакеты закреплены точными версиями и lockfile. Исходные уведомления зависимостей собраны в [THIRD-PARTY-NOTICES](https://github.com/cj-isus/avitolog/blob/main/mvp/THIRD-PARTY-NOTICES.md). Для одного транзитивного npm-пакета текст лицензии не найден; метаданные MIT и пробел описаны отдельно. Лицензия собственных исходников проекта пока не выбрана. Каталожные проекты Avito не встроены целиком: использованы результаты source-review и идеи контрактов; произвольное копирование файлов под разными лицензиями не выполнялось.

## Первый полный сценарий

1. Задать рост, диаметр колёс и верхний бюджет. По умолчанию — 196 см, 29″, 60 000 ₽.
2. Добавить карточку вручную, импортировать версионированный JSON или попробовать шесть явно вымышленных примеров. DOM-захват из установленного расширения — отдельный адаптер с отдельной проверкой разрешений.
3. Внести отсутствующие заявленные характеристики. Неизвестное не становится подходящим; маркировка XL сама по себе не доказывает посадку.
4. Выбрать до четырёх карточек и сравнить цену, параметры, источник сведений и заданный резерв.
5. Посмотреть цены выбранных аналогов. Три других примера — технический минимум текущего демонстрационного расчёта, а не статистическое обоснование достаточной выборки для рынка.
6. Подготовить два вопроса и, по желанию, свою сумму предложения. Текст условный и редактируемый; его можно скопировать. Отправки продавцу нет.
7. Сохранить JSON для следующего сеанса. Данные остаются в браузере; резервная копия не создаётся автоматически в облаке.

У вымышленных A/B/C цены 52/59/55 тыс. ₽. Резервы 3,5/4,5/4 тыс. ₽ заданы для интерфейса и не являются диагнозом ремонта. Поэтому B с полным заданным бюджетом 63,5 тыс. ₽ должен иметь причину исключения, несмотря на привлекательный обвес. Реальные карточки не смешиваются с демо в расчёте аналогов.

## Что проверено на первой сборке

На Node22.21.1 завершены установка закреплённых зависимостей, `wxt prepare`, TypeScript7 typecheck, production build расширения MV3 и отдельный Vite web-preview. **17 локальных тестов прошли**, включая строгую цену и идентичность DOM, дубли по Avito ID, свежий снимок, лимит200, конкурентные записи и полный откат импорта.

В изолированном Chrome прошли **15 браузерных сценариев** на синтетических данных: пустое состояние → демо → сравнение → ориентиры → условный черновик; смена кандидата сбрасывает прежний текст; ручные неизвестные → исправление → сохранение/перезагрузка; недопустимые URL/JSON; экспорт/импорт; пересчёт требований; клавиатура и диалоги. Проверены размеры1440/390/380px; ошибок JavaScript и внешних запросов в локальном прогоне не обнаружено. Исходники оставались неизменными во время финального прогона; контрольные хеши сохранены в [verification.json](https://github.com/cj-isus/avitolog/blob/main/mvp/verification.json).

Это доказательства локального starter. Реальный browser grant, установка расширения в пользовательском профиле, чтение живой площадки, LLM и точность рыночной оценки этим не проверены. Сгенерированные изображения хранятся отдельно и не используются как evidence работоспособности.

## Почему такой состав

Обзор не нашёл проверенной готовой модели, которая достоверно оценивает конкретную сборку и износ велосипеда по объявлению. Фреймворк браузерного агента решает другую часть задачи. Полный форк NanoBrowser добавил бы широкое управление браузером; Python/CDP-серверы — отдельную среду. Для проверки короткого пользовательского пути WXT и локальная база дают более узкую, обозримую стартовую систему. Это инженерный выбор по составу, а не измеренное превосходство или экономия времени.

Собственная логика остаётся необходимой на границе данных и решения: идентичность объявления, статус каждого поля, сопоставимость, причины исключения, недостаток данных и привязка черновика. Подробные основания — [[mvp-oss-components|в source-аудите]].

## Что вводить следующими проверяемыми частями

**Адаптер Avito.** На согласованной выборке открытых пользователем карточек проверить ID/цену/описание, снятые объявления, captcha и дрейф разметки. Только после этого оценивать расширение на живой площадке. Успех fixture не переносится на live DOM или browser permission.

**Извлечение с ИИ.** Добавить отдельный адаптер модели за прокси или локальным сервисом. Секреты не помещать в extension bundle. Модель получает выбранные поля, возвращает типизированные утверждения со ссылками на снимок; её результат не управляет отправкой сообщений. Протокол Snapshot и неизменяемый журнал ещё предстоит выделить из текущей записи карточки.

**Качество сравнения.** Собрать небольшой размеченный набор с механиком: существенные признаки, несовместимые аналоги, неизвестное и причины решения. Сравнить правила, ИИ и ручную работу по [[recommendation-evaluation|плану оценки]], включая стоимость перепроверки.

**Расширение UX.** Карта от Пролетарской, анализ фотографий, мобильный осмотр и граф доказательств показаны в [[mvp-gallery|десяти концептах]], но не реализованы в starter. Добавлять их стоит после проверки полезности основного пути, а не потому, что они присутствуют на изображениях.

Экономический критерий — полезный оплачиваемый результат после полной стоимости работы, а не количество экранов или сообщений. См. [[demand-economics-findings|выводы о спросе]] и [[unit-economics|экономику одного случая]].
