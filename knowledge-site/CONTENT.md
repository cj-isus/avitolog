# Как пополнять граф знаний

Канонические материалы хранятся в `research/`. Сайт — их производное представление; страницы графа не редактируются вручную.

1. Дополнить карточку в `research/data/deep-reviews.json`. Сохранить уровень проверки, дату, лицензию, ограничения и первичные ссылки. Не выдавать прочтение исходников за проверку работающего проекта.
2. Обновить связанный исследовательский текст, каталог и CSV существующими скриптами базы.
3. Если появилось новое направление, добавить его в `groupDefinitions` экспортера. Для нового проекта указать подтверждённые возможности в `projectCapabilities`; отсутствие связи лучше предположения по названию.
4. Закоммитить материалы. Обычная сборка читает только разрешённые файлы указанного Git-коммита и создаёт новые Markdown-страницы.

Самостоятельные статьи можно добавлять в `research/notes/`, включая вложенные папки. Каждая `.md`-заметка станет отдельным узлом в разделе «Исследования». Заголовок берётся из `title` во frontmatter либо первого H1; относительные ссылки на соседние заметки и wikilinks связывают их в графе. Поддерживаются ссылки на существующие узлы, например `[[projects/alexbutiev--avito-personal-mcp|Персональный MCP]]` и `[[capabilities/pricing|Оценка]]`. Не добавлять в этот раздел переписки, секреты и личные файлы.

Экспортёр публикует 37 подробных карточек текущего снимка, шесть смежных проектов, направления, возможности и отдельные исследовательские заметки. Числа вычисляются из данных и меняются при пополнении. Все 1 811 записей поисковой выборки доступны для скачивания, но не становятся отдельными узлами.

`--working-tree` предназначен только для локального предпросмотра до коммита. У таких страниц есть видимая пометка; их источник не считается закреплённым. Публикация должна использовать `--ref` с Git-коммитом.

Пример локального предпросмотра:

```powershell
node knowledge-site/export-content.mjs --repository . --ref HEAD --working-tree --quartz .artifacts/quartz --out .artifacts/quartz/site-content --source-url https://github.com/cj-isus/avitolog
```

Выходная папка должна быть пустой и находиться внутри изолированного Quartz. Экспортёр никогда не обходит репозиторий целиком. Разрешены два JSON, два CSV, четыре исследовательских Markdown-файла и заметки только из `research/notes/`; переписки, доказательства действий в аккаунте, вложения и настройки окружения в публикацию не входят.
